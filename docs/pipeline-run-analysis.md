### 2-4. MPS 열 스로틀링(Thermal Throttling) 분석

**현상**: Epoch 1에서만 발생. Epoch 2·3은 정상.

**원인**:
- MacBook의 MPS(Apple Silicon GPU)는 지속 부하 시 칩 온도가 임계값을 초과하면 클럭을 자동 감속한다.
- 학습 초반(cold start)에는 방열이 따라가지 못해 클럭이 급격히 내려간다.
- Epoch 1이 끝날 무렵 시스템이 열적 평형에 도달하고, Epoch 2·3은 그 상태에서 안정 동작한다.

**근거**:
- 구간 `1400→1600`에서 18.8s/스텝 — 정상(2.6s/스텝)의 **7.2배** 느림
- `1000→1200`은 2.6s/스텝(정상)으로 일시 회복 후 재차 스로틀링 — 온도 불균일 냉각 패턴과 일치
- Epoch 2 시작 직후(Epoch 1 종료 2분 후)부터 즉시 안정 속도 → 열이 어느 정도 식은 뒤 평형 달성

## 5. 개선 포인트

### 5-1. MPS 스로틀링 — Epoch 1 손실 2시간 13분

**대응 방안**:

```python
# 방법 A: 배치 크기 축소로 MPS 열 발생 억제
# batch_size=32 → 16으로 줄이면 MPS 부하 감소 (대신 스텝 수 2배)

# 방법 B: torch.mps.empty_cache() 주기적 호출
if step % 100 == 0 and device.type == "mps":
    torch.mps.empty_cache()

# 방법 C: 쿨링 대기 (비권장 — 시간 손실)
```

실용적인 접근: 방법 B를 `train_epoch` 로그 구간에 추가하는 것이 코드 변경 최소화 대비 효과적이다.

---

### 5-2. `num_workers=0` — 동기 데이터 로딩 (매 스텝 적용)

`src/preprocess.py:213–215`. 이미 `docs/epoch-performance.md`에서 상세 분석함. 요약:

```python
# 현재
DataLoader(train_dataset, batch_size=batch_size, shuffle=True)

# 개선
DataLoader(train_dataset, batch_size=batch_size, shuffle=True,
           num_workers=2, pin_memory=True, persistent_workers=True)
```

---

### 5-3. Test 추론 디바이스 — CPU 강제의 비용

`src/evaluate.py`가 MPS 스로틀링을 이유로 CPU를 사용하지만, Epoch 2·3 실행 결과를 보면 **훈련이 끝난 직후에는 MPS가 안정 상태**다. 추론 단계 진입 시점에서 MPS를 먼저 시도하되, 온도 감지 후 fallback하는 방식이 더 합리적이다.

```python
# evaluate.py — 현재 (CPU 강제)
device = torch.device("cpu")  # MPS 스로틀링 방지

# 개선 제안: 학습 직후라면 MPS 사용 가능
device = get_device()  # mps → cpu 자동 선택 (train.py와 동일 함수 재사용)
```

이 변경만으로 추론 시간이 약 27분 → 10분으로 단축 가능하다.

---

### 5-4. AMP 미사용

`src/train.py` 전 구간 fp32. MPS는 `bfloat16`을 지원하며, 적용 시 Epoch당 30~50% 단축 기대.  
상세 코드는 `docs/epoch-performance.md` 전략 4 참조.
